# 第 03 项：EPUB 翻页与同布局定位修复

日期：2026-10-22。分支：`codex/reader-turn-location-fixes`；前置提交：01A `aaeb4ba`、02 `8eef9ed`。用户已批准复审后按方案实施，并使用其提供的 EPUB 验证。本项不修改 TXT / PDF 生产实现。

## 影响与实施

- 相邻翻页从“可见段落数量”改为实际正文视口的 0.92 倍位移，保留约 8% 上下文；书首、书尾按可滚动距离收敛。长段落、页底半段与跨段尾均使用同一规则。
- 通过 Flutter 公共 `ScrollPosition` 移动像素，不传负数 alignment，不导入依赖私有 API。横向模式在现有容器内同步换位置；纵向相邻翻页保留 250ms / easeOutCubic。
- 最多保留 48 次已完成翻页的锚点，支持边界不足一屏时的准确往返。手动拖动、显式跳转、布局/图片尺寸变化或实际位置不匹配即失效；未完成、被打断和无位移操作不写入历史。
- 索引与段内偏移在同一目标绘制前应用。未挂载请求保留完整位置，不再循环等待挂载 5 秒；恢复完成前，引擎返回已接纳目标，避免临时段首进入自动保存。书籍元数据中的完整位置也被保留。
- 目录、书签、进度跳转统一经过该定位路径。**纵向进度跳转改为直接定位，不再使用双列表滚动过渡；普通相邻纵向翻页仍有动画。**
- 旧导航的异步完成通过代次校验失效。图片读取改用顶层 `compute` 回调，只传两个字符串，防止实例闭包携带不可跨 isolate 传递的滚动对象/Future；错误仍使用原有图片错误占位反馈。

公共方法签名、`ReadingPosition` JSON、数据库 schema、EPUB 枚举版本、段落编号、章节映射、高亮编号、百分比算法均未改变；没有新增依赖。位置仍由引擎拥有，不在 Widget/Manager 增设第二份位置。

## 验证标准与风险

已批准的标准：两模式现有 8 个定位用例转绿；同布局段内误差不超过 2 个逻辑像素；连续前进不漏读、不倒退；跨长段尾、短书/空书、边界往返、冷恢复、导航打断和图文混排可继续阅读。图片尺寸变化会取消旧几何导航，但完整图片加载保位仍属 10。旧存档只有段落索引时只能恢复到段首，无法还原未保存的段内信息。

本次不实现跨字体/宽度的字符锚点（05）、稳定图片占位（10）、进度语义（14）、图片缓存上限（16），也不修改共用横向动画（08/13）。不将定位通过解释为整个阅读器流畅度达标。

真实文件定位测试修复前 0/4、修复后 4/4：
- 旧实现两模式均从长段落 149859 直接跳到 149860；新实现留在该长段，leading 从 0 变为约 -0.9203125，继续向前读。

## 设备与性能

Android 16 / x86_64 的 `Medium_Phone` 模拟器，1080×2400、420dpi（DPR 2.625）、60Hz，Impeller OpenGLES；Flutter 3.38.9 / Dart 3.10.8。用同一个 profile APK 编入 `8eef9ed` 的旧 EPUB 引擎与当前引擎，每模式先旧后新，5 次预热、30 次测量，进程重启后三轮，共 **18 个场景全部成功**。横向包含真实共用截图动画，纵向经过引擎，纯滚动通过滚动位置执行等距运动。

- 横向三轮均降低了超预算帧占比，但 build/raster P95 仍超过预算，**不能验收为流畅度达标**。共用动画衔接、截图成本仍留在 08/13。

- 同起点不等于同工作负载：旧实现按段数跨越，新实现按 0.92 视口移动，经过的正文不同。先旧后新、仅三轮且在模拟器测量，不能将所有差异归因于算法或外推至真机。

- 原始 environment 事件在有效 surface 几何到达前记录为 0×0、DPR 1；完整保留该记录。设备尺寸用 `adb wm size/density` 另行核实，场景帧预算读取当时的显示器刷新率，不用这条初始几何数据计算。

这覆盖正常保存后的冷启动，不代表在未完成保存时强杀进程也不会丢最后一次位置；横向冷恢复的引擎路径由自动化测试覆盖，未另做完整应用 release 冷启动场景。

源文件、APK 指纹、各轮原始统计和完整应用恢复事件见 [机器可读证据](baselines/epub_turn_fix_03_2026-10-22.json)。原始失败记录保留，不与成功运行混合统计。

### 测量准备中确认的存储风险

初次两次配对运行因样本消失中断，分别产生 6 个和 5 个场景错误，保留在忽略目录 `epub-paired/results`、`results-final`，不能混入成功性能统计。模拟器 `/data` 仅余约 583MiB；Android `installd` 明确记录了清除 193MB 的 `cache/epub-03.epub` 及合成临时文件，证实是存储压力回收缓存，而非翻页解析正确性的结果。

测量改为将授权文件存入专用测试安装的 `files/epub-03.epub`，删除自己的中转副本；配对入口不再创建无用合成缓存。原书未改动，也未清理其他应用或用户文件。

生产相关风险另列：`MainActivity.kt` 的 `copyUriToTempFile` 将 SAF 临时书源放在 `cacheDir/book_sources`。本轮没有通过真实 SAF 重现生产故障，但系统清理缓存的证据说明长期保留大型临时书源需要单独复审；第 03 项不改书源生命周期。
