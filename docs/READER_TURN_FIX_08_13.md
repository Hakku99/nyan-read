# 第 08 / 13 项：横向翻页时序与绘制

日期：2026-10-23。当前分支 `codex/reader-turn-location-fixes`，对照基准 `3878caf`（第 05 项）。按用户授权先实施 08，再试验并筛选 13 的优化。第 08 项现已独立提交为 `90bfdf9`，拆分验证见 [08 交付说明](READER_TURN_FIX_08.md)；第 13 项候选继续保留在工作区，尚未验收。以下性能与设备记录对应当时 08＋13 的联合版本；没有合并或推送。

## 08：先准备目标页，再开始移动

- 旧页截图覆盖实际正文，导航只派发一次；目标文字布局、PDF 页面图像或 EPUB 可见图片就绪后才开始 360ms 横向动画。删除“动画中途才切换内容”的时序。
- `PageTurnRequest` 贯穿 UI 请求、导航队列与呈现等待。截图未完成时取消，不再产生迟到翻页；导航已接受时取消，保留引擎真实位置，不回滚、不重派。
- UI 原来的 3 秒保护现在先取消请求，再释放输入；不会只开锁后绕过繁忙动画直接翻页。队列恢复与本次操作的错误分开处理，错误能够到达 UI 的现有本地化提示。
- 截图等待限 350ms；导航与目标就绪各限 1500ms，另受整体 3 秒保护。截图不可用时只执行一次直接翻页；目标图像超时则显示阅读器正常加载状态。不能取消底层 GPU 回读，但最多保留一个未返回任务，其迟到图像立即释放。
- 模式、字号、行距、字体、颜色、系统布局变化及后台/退出会取消旧呈现；打开控制浮层也取消。正文及滚动组件一直挂载。
- 完整应用发现并修复额外的订阅遗漏：偏好服务使用普通 Riverpod `Provider`，仅 watch 服务对象并不订阅其字段变化。正文原先只选择 `renderEpoch`，程序化切换模式可能使引擎已切换、手势容器仍旧禁用。现在通过 Controller 通知，选择模式与排版所需的最少字段。

## 13：根据测量选择优化

第一轮候选只缩小截图范围、使用双线性过滤并删除旧黑色边缘渐变。结果不足：文字页 raster P95 仍约 17–18ms。第二轮候选让 TXT/EPUB 就绪后的目标页也截图，动画仅移动两张图片；实际正文通过静态 opacity 0 暂停绘制，状态、布局、选择控件仍挂载。PDF 本来就是图片，保持单截图。

第二轮探索性单轮结果（08 → 08+13，不是最终三轮验收）：TXT 超预算帧 10.12% → 2.01%，EPUB 23.56% → 1.11%；完成 P95 分别增加约 19ms / 32ms。这个结果支持保留双页图片方案，后续正式结果见本报告末尾。

- 截图维持设备像素分辨率，未通过缩小截图或缩短 360ms 动画取得改善。
- 新增目标截图的 RGBA 大小限制为 16 MiB；更大视口回退到实际正文绘制，不承诺同等流畅度。普通手机本次约增加一张 9–10 MiB 图像；包括旧页约 19–20 MiB，尚不包含 GPU 临时表面和图像缓存。
- 完成、取消、异常、组件销毁均释放已接收的两张截图；迟到截图也有释放测试。没有新增整书缓存、图像解码缓存或第三方依赖。
- 增加目标截图有准备时间成本；总完成耗时包含这段成本，不能只报告动画帧更快而隐去响应时间。

## 契约与回滚

新增可选 `PagePresentationCapability.waitForPagePresentation(PageTurnRequest)`；`ReaderController.nextPage/previousPage` 增加可选请求参数，以及代理真实位置和呈现就绪的方法。原有调用仍可用；`ReaderEngine` 导航方法、`ReadingPosition` JSON、章节定位与 SQLite schema 不变。PDF 使用 `pdfx` 的公共 builder 和图片 provider；没有引用私有 `src/` API。

回滚 13 可关闭目标截图并恢复单页呈现，不撤销 08 的取消/就绪顺序。回滚 08 应成组撤销请求令牌、Controller/UI 调度和图片就绪能力，保留第 05 项稳定挂载及位置字段。两者均无需数据库迁移或数据回填。

## 验证方法与边界

性能基线由 `prepare_turn_pair.py` 从 `3878caf` 提取原 TXT/EPUB/PDF 引擎和原动画容器，与当前实现编入同一个 profile APK。默认不依赖本地第 08 项探索检查点；`--pilot` 仅用于本地探索重现。

最终矩阵为三轮、每轮六场景、每场景修复前后两版本：TXT 普通/长段、EPUB 普通/长段/图片区域、100 页合成文本 PDF。顺序按 AB、BA、AB 交替；每场景测量 12 次（6 前进、6 后退），普通场景预热两次、图片区域预热 12 次，再统一恢复起点。记录每步实际位置，用于核对前后工作量；图片场景是预热后的路径，冷图首次解压不能混为同一性能结论。

UI/raster FrameTiming、调用至完成并经过下一帧的耗时、截图/导航/就绪/动画阶段和进程 RSS 分开记录。不是手指触摸至显示屏发光的测量，也不是完整应用持续帧率。完整应用另使用 release 包，经真实 hit testing/gesture recognizer 路径注入指针，检查点击、横向滑动、快速连点、模式和浮层取消、SQLite 保存及强制结束后恢复。

样本由用户授权提供，未提交正文、源文件或书页截图：

- TXT 9,190,763 bytes；SHA-256 `908BC3552974C31F1ED3C8C25EE83E289773CA44F7C84C84AA1A16A4DC5844A9`。
- EPUB 193,460,451 bytes；SHA-256 `486FFF823E05F54E623528CE488B211B6196C6AA751272B74E6565EF133D3915`。

探索中的无效运行不纳入性能结论：长日志截断；模拟器低空间期间，缓存中的 PDF 测试文件被清掉；APK 安装失败后误启动旧包。随后使用分片结果、保留跨日志轮转事件、非缓存测试目录及安装失败立即退出修正。自动审核曾拒绝卸载，核对首次安装时间、无数据库和本轮安装记录后确认是专用测试安装；后续更新只临时移除本轮复制的样本以腾空间。用户源文件和原有数据未清理。

## 正式三轮性能结果

环境：Android 16 x86_64，1080×2400、DPR 2.625、60Hz；Flutter 3.38.9 / Dart 3.10.8；Impeller OpenGLES，NVIDIA RTX 4070 Ti SUPER 硬件后端。采样期间未运行构建或重型测试。36 个场景、432 次测量翻页，加上预热共 564 次派发。前后各 216 步的位置轨迹逐步比较，段落/页码/字符相同，几何在 2 逻辑像素内，**0 处不一致**；修复版 216 次目标就绪检查全部成功。

相对第 05 项，08＋13 的完成时间增加约 84–117ms；其中混合了 08 就绪等待和 13 截图准备，不能全部归因于 13。修复版阶段 P95：旧页截图约 20–22ms，导航 TXT/EPUB 约 20–29ms、PDF <1ms，就绪约 18–51ms，目标截图约 35–39ms；这些分位数不能简单相加。360ms 配置对应实际动画完成约 380–386ms，受到帧边界调度影响。未测触摸到光子的端到端延迟。

原始 `warmupPhases` 调试字段包含前一场景残留，未用于任何结论；测量阶段的 `phases` 每场景均清空并核对为 12 条。生成器随后补上场景开始时清空，仅修正预热诊断记录，生产代码与正式测量阶段未变。记录中的 `profile_pair.dart` 哈希对应实际编译采样的文件。
