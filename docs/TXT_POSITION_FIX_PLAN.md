# 第 02 项：TXT 定位修复评审方案

状态：用户已批准从 main 创建新分支，依次实施 01A、02；当前分支 `codex/reader-turn-location-fixes`。前置证据见 [第 01 项基线](READER_NAVIGATION_BASELINE.md)，实施与验收记录见 [修复报告](READER_TURN_FIXES_01A_02.md)。本文保留动工前的影响、风险和验收范围。

## 复审后的排序

保留原有 02～21 的编号。第 01 项在 Android profile 中暴露了新的发布阻断风险：横向翻页截图读取 `debugNeedsPaint`。应插入 **01A：消除正式构建的横向翻页异常（P0，复杂度 S～M）**，再做 **02：TXT 定位准确性（P0，复杂度 M～L）**。原 08 的中途切换内容、13 的截图性能优化仍独立处理，不合并为一次大改。

第 02 项优先级不降低。用户感受到的“不顺”至少包含两类原因：位置跳错，以及画面输出/动画异常。定位测试能证明前者，不能代替帧性能测试。

01A 的批准范围：修正截图准备与异常回退，去掉生产控制流对 debug-only getter 的依赖，确保画面未就绪、截图失败或页面已销毁时不会重复执行或无声丢失翻页。影响覆盖三格式横向模式；风险是截图时序、旧画面闪现和重复 dispatch。验收需在 profile 和 release 中实际走截图路径，三格式均成功翻页，故障回退只执行一次；保留原有 debug 测试。

## 影响

目标是在相同布局下，让 TXT 的下一页持续向前、上一页正确返回、保存的段内位置正确恢复。

拟改动集中在 `lib/modules/reader/reader_engine/txt/txt_reader.dart`：

- 超长段落的视口内移动与段尾衔接。
- 当前位置、历史锚点及 `goToPosition` 的偏移解释。
- 列表尚未挂载时保留完整待恢复位置，挂载后消费一次。
- 必要的内部视口偏移适配与异步操作失效检查。

**契约影响：不计划改变 `ReaderEngine`、`ReadingPosition`、`ChapterLocator` 的公共方法签名或序列化字段，不改变数据库 schema，不新增依赖。** 现有段落索引、书签、高亮、章节映射继续有效。阅读位置依然由引擎拥有；不在 Widget、Manager 中另建一份当前位置。

既有位置只存段落索引时，继续恢复到该段落开头。有有效 leading/trailing 时，同布局恢复段内位置。异常、缺失、越界值应安全回退，不应造成崩溃或走到书外。

本项不重新拆分 TXT 段落，不改解析后的段落编号，不改变页码估算或全书进度算法，也不承诺字体/宽度变化后的逐字恢复。跨布局的精确字符锚点属于第 05 项：当前旧数据只有几何边界，没有字符位置，不能凭空恢复不存在的信息。

## 风险与拟采用的实现方向

### 1. 当前公式误用了坐标含义

当前 `_alignmentFromEdges` 及长段落分支把 leading 除以 `1 - 段落高度/视口高度`，再限制在 0～1。

依赖的 `ItemScrollController` 参数实际代表“段落顶部在视口中的位置”，不是段落内部进度。因此，负 leading 被夹到 0 会回到段首；高于一屏的段落则可能被反向挪回屏幕内。

不能只删除 clamp、把负数传入 alignment：当前固定版本 0.3.8 的公开说明要求 alignment 位于 0～1。即使某条内部路径暂时接受负值，也不能把它当稳定契约。

### 2. 候选：段落定位与像素偏移分离

- 普通的索引跳转继续使用公开 `ItemScrollController`。
- 同布局段内移动，候选使用公开 `ScrollOffsetController.animateScroll`：偏移 = 所需视口位移 × 实际正文视口高度。超长段落目标步长沿用约 0.92 屏，保留约 8% 的上下文重叠；书首/书尾按可移动距离收敛。
- 从远处恢复：先建立目标段落锚点，再应用保存的段内偏移；将两阶段过程视为一次恢复，防止中间位置被保存或显示成一次额外翻页。
- 过滤真正可见项，覆盖长段落顶部、中部、尾部以及邻接短段落，不能只在“回调列表恰好只有一个 item”时才正确。
- 先验证当前操作仍属于同一引擎、同一布局/挂载代次；新导航、布局变更或销毁应使旧操作失效。有限次等待真实布局，禁止靠无限重试或固定长延时凑结果。

**风险：该偏移 API 被依赖标为 experimental。** 第 01 项仅验证了其公开接口在 120px 和 2560px item 内正反偏移成立，不代表边界、切换和快速输入都已验证。适配应集中在 TXT 引擎内部，避免散落调用，不导入任何依赖的 `src/`。

`animateScroll` 只提供动画接口；极短 duration 也不等于同步跳转。两阶段恢复可能闪一下段首、引发动画叠加，或在完成前被保存。这是本项必须验证的风险，不能先写一个 1ms 动画就宣布完成。若公开 API 无法满足无闪跳要求，应在同一评审范围内重新提出方案，而非偷偷采用私有 API 或改变数据模型。

### 3. 历史与生命周期

实施选择：验证后采用稳定的 Flutter 公共 `ScrollPosition`，通过 `ScrollMetricsNotification` 的公开上下文取得；没有采用 experimental 的 `ScrollOffsetController`。公开 `ItemScrollController.jumpTo(index)` 与 `ScrollPosition.jumpTo(pixelOffset)` 同步组合，在首个目标帧即得到正确偏移。90、588.8、6400 逻辑像素的独立接口测试覆盖此契约，避免 1ms 动画的额外纠偏帧。此选择属于已批准的内部视口偏移适配范围，没有更改公共契约或数据模型。

正确解释历史锚点可以修好立即“下一页→上一页”的段内偏差。**手动滚动后仍使用过期历史**是另一个问题，保留第 04 项处理，相关失败用例必须继续保留，不能把它混入本项的“全部修复”声明。

冷恢复要保留挂载前位置，但不能让现有“初始化阶段 await goToPosition”的调用死等视图挂载；未挂载时应接纳待恢复目标并按现有调用顺序返回。挂载后完成恢复时，需要避免把过渡状态写回数据库。这可能需要检视保存/刷新时序；若实际必须改变 Manager 持久化流程，需另行明确范围和风险，不默默扩大修改面。

## 验证与验收

### 必须从红转绿

1. TXT tap/swipe 的长段落单次前进、段内 next→previous、序列化位置恢复、全新引擎挂载前恢复。
2. 用户提供的真实 TXT：两种模式下最长段落前进、普通段内往返。
3. 同布局段落索引准确，段内恢复误差不超过 **2 个逻辑像素**；不能用“同一段就算成功”代替。

### 修复时补齐的边界

- 段高约 0.99/1.00/1.01/2/10 屏；单段整书、空文件、短书、空行、末段、CRLF、CJK、emoji。
- 超长段落连续至少 20 次向前，直到段尾并进入后续文本；书尾再翻保持边界，不能倒退或循环；反向逐次返回。
- 同布局前后往返至少 20 次，不累积偏差；异步中切书、卸载、旋转、连续导航，旧结果不覆盖新目标。
- 书签跳转、目录跳转、进度跳转及其后再翻页；章节高亮与可见段落一致。
- 保存进程退出前位置，重建引擎后恢复；另做完整应用退出/重开检查，验证数据库中的位置没有被中间状态覆盖。
- 两套字体、不同字号行高、横竖屏、Android 字体缩放。跨布局先验收目标段落及无倒退；逐字保位留待第 05 项。

### 不能退化的对照

- 真实 TXT 的普通区域 30 次连续前进仍通过，无跳过未读文本。不要把本次观察到的 0.869～0.995 屏强行当成所有书籍的固定步长要求。
- EPUB、PDF 基线的已知失败可以保留，但不得新增失败；第 04/05 项未修的失败不得删除、跳过或降低阈值。
- 现有 reader/persistence/settings 测试继续通过；`flutter analyze`、设计 token 检查及项目要求的针对性测试执行并记录。
- 在同一模拟器、同一 profile 环境重复测量至少 3 轮。对照 build/raster 分位耗时、超时帧比例及操作完成时间，不只看平均 FPS。新增恢复闪跳、明显帧耗时退化需查明后再交付。
- 完整横向动画验收依赖 01A；debug 测试通过不能代替 profile/release。
